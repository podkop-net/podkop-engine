# История изменений

[English](CHANGELOG.md)

Выпуски помечаются тегом `v<версия sing-box>-r<N>`; один номер ревизии охватывает все линии sing-box,
собранные в ней (`v1.13.21-r18` и `v1.14.4-r18` — один выпуск). В каждой записи — что изменилось
по сравнению с прошлым выпуском и что это значит для пользователя; линия названа, только если
изменение касалось одной линии. Что делает каждый патч — [docs/PATCHES.md](docs/PATCHES.md); опции — [docs/FEATURES.ru.md](docs/FEATURES.ru.md);
полные заметки и пакеты — [выпуски на GitHub](https://github.com/podkop-net/podkop-engine/releases).

## r29 — 2026-11-25

sing-box 1.14.4

- **urltest:** в режимах `loss` и `balance` проверки потерь идут, только пока через группу идут соединения. Группа, которая служит запасной для другой, по-прежнему тестируется вместе с ней, но через её серверы ничего не скачивается, пока основная группа не перешла на неё, и не дольше её `idle_timeout` после последнего соединения. Измерено: через бездействующую запасную группу 0 байт, r28 проверял её так же часто, как рабочую.
- **urltest:** группа, через которую пошли соединения и у которой нет подсчёта потерь, один раз проверяет каждый сервер на 1 МиБ, поэтому потери решают через секунды после перехода на запасную группу, а не после четырёх проверок по 256 КиБ (2 часа). Балансировка без соединений отдыхает: её серверы больше не проверяются скачиванием при каждой смене лучших трёх (до 64 КиБ за круг). Переключение ждёт идущую для него проверку потерь.
- **urltest:** группа после простоя проверяет свои серверы при первом же соединении, как и задумано. Эта проверка пропускалась, и первые соединения шли по выбору, сделанному до простоя, пока через `interval` не приходила следующая.
- **входы:** вместе с входом закрываются соединения, которые он ещё держит. Раньше keep-alive-соединение HTTP-прокси после перезапуска один раз отвечало «502 Bad Gateway».
- **встраивание:** `tls.ErrRealityVerification` (текст прежний), `adapter.DetectOutcomeKey`, `rule.RemoteStart` в контексте (`SING_BOX_RULE_SET_START_EMPTY` остаётся), `urltest.ContextWithTest` для своих проверок программы через группу; в `/proxies` у группы в режиме balance без соединений нет `balance`. Ничего не убрано.

## r28 — 2026-11-21

sing-box 1.14.4

- **выходы:** `finalmask`, маска fragment из Xray в дайлере: ClientHello режется на мелкие записи TLS под TLS, REALITY и любым транспортом. У двух российских провайдеров, которые отбрасывают ClientHello к части серверов, записи по 11–24 байта двумя TCP-кусками прошли 165 раз из 168, целый hello — ни разу.
- **tls:** `certificate_sha256` из sing-box 1.15 закрепляет сертификат сервера (и самоподписанный) или, как в Xray, сертификат CA из его цепочки; `certificate_server_name` проверяет сертификат по другим именам, чем отправленное (`vcn` Xray).
- **decode-link:** ссылки дают `fm` (`finalmask`; в ссылках Hysteria 2 — salamander, gecko и смену портов), `pcs` и `pinSHA256` (`certificate_sha256`), `vcn` (`certificate_server_name`): серверы с самоподписанными сертификатами теперь подключаются. `realm` Hysteria по-прежнему отвергается.
- **urltest, probesock, детектор:** balance держит не больше 4096 устройств; тест читает не больше 64 КБ заголовков ответа; тесты больше не удерживают заменённые выходы в памяти; дальняя сторона не может удержать пробу потерь; итог рукопожатий сервера пишется в файл кэша с ограниченной частотой.
- **version:** в строке Features добавлены `dialer.finalmask`, `tls.certificate_sha256` и `tls.certificate_server_name`.

## r27 — 2026-11-15

sing-box 1.14.4 · podkop-exp 0.8.16, 0.8.17

- **сниффер:** uTP опознаётся только по SYN, как в Xray, а DHT (BEP 5) — новый сниффер пакетов, так что правило `protocol: bittorrent` видит сокеты qBittorrent, Transmission, aria2 и rTorrent. Из 200 000 случайных пакетов ни один не принят за BitTorrent (прежняя проверка пропускала около одного из 6400).
- **urltest:** в режимах `loss` и `balance` потери участников hysteria2 и tuic считаются по пакетам их соединения QUIC, по цене, измеренной для hysteria2 (форки podkop-net/quic-go и podkop-net/sing-quic). Раньше такой участник выбирался по одной задержке.

## r26 — 2026-11-14

sing-box 1.14.4 · podkop-exp 0.8.15

Загрузка начинается с пути, который принёс прошлый файл хоста; следующий путь начинается рядом, когда первый молчит или стоит, не больше трёх сразу. - **пакет:** в `podkop-engine` нет инструментов networkquality, STUN и schema: бинарь меньше на 328 КБ (aarch64) и 459 КБ (mipsel).

## r24 — 2026-11-12

sing-box 1.14.4 · podkop-exp 0.8.13

- **urltest:** опция `urls` — несколько адресов проверки, по одному на раунд по очереди, один и тот же во всех группах; задержка участника — медиана последних раундов, а участник, не ответивший адресу раунда, проверяется ещё раз адресом, который через него раньше отвечал. Проверки всех групп идут одним проверяющим, а через один и тот же первый сервер начинаются с разницей в 2 с.
- **urltest:** опция `mode`: `fastest` (по умолчанию, как раньше), `loss` (задержки с поправкой на потери, которые проба в 256 КБ считает по пакетам своего соединения TCP) и `balance` (соединения распределяются по адресу источника между лучшими участниками).
- **REALITY, uTLS:** `fragment` и `record_fragment` действуют на ClientHello REALITY, как на ClientHello uTLS; раньше они принимались и молча не применялись. На пути с «заморозкой» по отпечатку: с `record_fragment` 15 подключений из 15, без него 0 из 15.
- **пакет:** форк sing-box — ровно тег upstream плюс патчи этого репозитория, это проверяется при каждой сборке.

## r21 — 2026-11-03

sing-box 1.14.4 · podkop-exp 0.8.9

- **DNS:** новые типы DNS-сервера: `group` спрашивает свои серверы по порядку списка или сначала самый быстрый по замеру и отставляет отказавший; `provider` спрашивает DNS провайдера, которые знает netifd. Группа из одних локальных или частных резолверов резервного DNS не получает.
- **встраивание:** для программ, которые встраивают sing-box (Go-бэкенд podkop-exp): по каждому серверу REALITY файл кэша хранит, оставались ли ClientHello без ответа, не сорвалось ли рукопожатие и не отверг ли сервер первого кандидата автосмены отпечатка; соединения считают байты и узнают, закончил ли поток удалённый конец; история URL-проверок хранит последнюю неудачу и итог последней проверки загрузкой.
- **urltest:** неудача, которую оборвал конец раунда или вызывающий, больше не считается сбоем участника.
- **Clash API:** в `/proxies` у группы urltest есть поле `fallbacks`, и клиент отличает неответивший сервер от непроверенного резервного выхода.
- **исправления:** дозвон через ws или httpupgrade кончается вместе со своим контекстом, а не ждёт сервер, который не отвечает на upgrade; `decode-link` принимает верный JSON с пробелами и адресами в `extra` (подписка из таких ссылок XHTTP оставалась без серверов).
