# Замеры

[English](BENCHMARKS.md)

podkop-engine против sing-box без патчей той же версии. Сначала — свежее сравнение (r27 против
1.14.4), затем прежние: они показывают, что дал патч, когда его делали.

Как мерилось свежее: оба бинаря собраны одинаково (Go 1.26.8, статически, `-trimpath`, теги пакета;
движок добавляет `podkop_slim`, поэтому в сравнение входит и то, что этот набор убирает). Каждый тест —
5 раундов на бинарь, по очереди; в таблицах — медианы. Разница засчитывается, когда p по Манну–Уитни
равно 0,008 (наименьшее возможное при 5 + 5 раундах). Для процессора на DNS-запрос и на соединение
она ещё должна выходить за прогон r27 против самого себя на той же машине (отношение A/A: x86_64 —
1,05 и 0,93, arm64 — 0,99 и 1,00). Разницы при p 0,03–0,1 показаны со своим p. Единичный результат,
который не повторили ни другая машина, ни родственный тест, не засчитывается; он назван под
таблицей.

## r27 против sing-box 1.14.4 (2026-11-17)

Две машины: **x86_64** — одно ядро AMD Ryzen 9 7950X3D, его делят sing-box и нагрузка, есть AES;
**arm64** — Neoverse, sing-box на одном ядре из 4, нагрузка на двух других, есть AES. Поэтому
числа «до отказа» у машин разные. Нагрузка — на той же машине; загрузки через прокси идут к тестовому серверу
через интернет. Роутеры (MT7621, Filogic 820) [ещё не измерены](#не-измерено).

| Тест | x86_64: без патчей → r27 | arm64: без патчей → r27 |
|---|---|---|
| REALITY к серверу Xray 26.9.9 | **отказ (0 из 10) → работает (10 из 10)** | **отказ (0 из 10) → работает (10 из 10)** |
| Трафик через прокси, процессор на ГБ: hysteria2, Trojan, Shadowsocks, REALITY на Xray 26.6.27 | одинаково | одинаково, кроме REALITY без flow: +25 % (p 0,008, не повторилось; см. ниже) |
| DNS, имя из списков (FakeIP), 500 запросов/с, процессор на запрос | 116 → 113 мкс, одинаково | 101 → 97 мкс (−4 %) |
| DNS, FakeIP до отказа: запросов в секунду | 8 788 → 12 110 (**+38 %**) | 10 060 → 18 120 (**+80 %**) |
| DNS, FakeIP до отказа: процессор на запрос | 72 → 39 мкс (−46 %) | 99 → 55 мкс (−44 %) |
| DNS, имя, которое спрашивается у вышестоящего сервера, 500/с, процессор на запрос | 153 → 209 мкс (**+37 %**, см. ниже) | 161 → 219 мкс (**+36 %**) |
| Соединения через вход mixed, процессор на соединение | одинаково | одинаково |
| Простой, 30 с после старта: RSS / анонимная память | 35,9 → 32,6 МБ / одинаково | 33,0 → 30,5 МБ / одинаково |
| Список из 100 000 доменов в source JSON: старт | 0,37 → 0,02 с | 0,68 → 0,05 с |
| Тот же список: анонимная память | −21 % | −20 % |
| Список из 100 000 подсетей в `.srs`: старт; анонимная память | 0,03 → 0,02 с; −15 % (p 0,056) | 0,05 → 0,03 с; −32 % |
| Список из 100 000 доменов в `.srs` | старт одинаково; анонимная память +15 % (p 0,095) | одинаково |
| Статический бинарь | 40,6 → 35,3 МБ | 37,9 → 33,0 МБ (mipsle: 42,9 → 37,6 МБ) |

- **Трафик через прокси** стоит процессору одинаково: код пересылки — из upstream. Загрузки упирались
  в путь (11 МБ/с на x86_64, 17–22 МБ/с на arm64), поэтому сравнивать стоит процессор на гигабайт.
  REALITY без flow на arm64 с r27 вышел на 25 % дороже на гигабайт на шумном пути; ни x86_64, ни
  Vision этого не показали, поэтому разницей это не считается.
- **DNS до отказа** быстрее, потому что движок держит горутины новой UDP-сессии наготове (r26).
- **Имя, которое спрашивается у вышестоящего DNS-сервера, стоит дороже**: движок отправляет каждый
  запрос со своего UDP-сокета (r4), а sing-box без патчей — все запросы через один сокет. По профилям
  процессора цена — около 55 мкс на запрос. Так сделано для провайдеров, которые ограничивают
  запросы с одного сокета (Яндекс DNS — около 20 в секунду). Имена из списков, на которые отвечает
  FakeIP, эту цену не платят.
- **Списки**: JSON-списки доменов строятся за один проход (r15). Списки доменов в `.srs` загружаются
  одинаково быстро у обоих; списки подсетей в `.srs` стартуют на треть быстрее (десятки миллисекунд).

## Прежние сравнения (сентябрь – начало ноября 2026)

Здесь выпуск podkop-engine того времени сравнивается с sing-box без патчей той же версии или, для
одной части, с кодом upstream. Это то, что дал патч, когда его делали; позже часть этих мест менялась
снова.

### Размер

Бинари, собранные одним Go 1.26.8, МиБ, 2026-10-02:

| Сборка | x86_64 | arm64 | armv7 | mipsle |
|---|---|---|---|---|
| sing-box 1.13.21 из OpenWrt 25.12, полный | 45,6 | 42,4 | 41,9 | 48,3 |
| sing-box 1.14.2 upstream, все возможности | 87,7 | 82,0 | 77,5 | 97,5 |
| podkop-engine 1.14.2-r7 | 32,7 | 30,3 | 30,0 | 34,5 |

С r9 пакет `podkop-engine` к тому же не содержит выходов, которые podkop не пишет (1.14 на x86_64:
24,3 МБ вместо 29,2).

### Память работающего sing-box

Стенд x86, одна и та же конфигурация podkop, 2026-10-02:

| | простой, со списком russia_inside | после 3000 имён FakeIP и 60 000 запросов |
|---|---|---|
| sing-box 1.12.22 из OpenWrt, tiny / полный | 30,1 / 37,7 МБ | |
| sing-box 1.13.21 из OpenWrt, tiny / полный | 32,5 / 40,3 МБ | 39–43 / 47–50 МБ |
| podkop-engine 1.13.21-r7 | 30 МБ | 41–44 МБ |
| podkop-engine 1.14.2-r7 | 34–35 МБ | 41–44 МБ |

Из этих 30–45 МБ RSS 22–28 МБ — страницы самого бинаря; своя память — 5–7 МБ в простое и 13–18 МБ
после нагрузки. Виртуальный размер любого sing-box — 1,2–1,3 ГБ (резервы Go): список процессов LuCI
показывает это как сотни процентов.

### FakeIP

Стенд x86, файл кэша в /tmp, 2026-10-02. «upstream» — сборка с кодом FakeIP из upstream 1.14.2; r7 —
хранилище podkop-engine в памяти.

| | upstream | r7 |
|---|---|---|
| Новых имён в секунду | 95 | 80 000–100 000 |
| Процессор на новое имя | 460–680 мкс | 38–50 мкс |
| Пачка из 100 новых имён, последний ответ | около 1040 мс | 2,1–4,8 мс |
| То же с файлом кэша на эмулированной SPI-NAND | около 1170 мс | 1,6–4,0 мс |
| Записано в файл кэша на 30 000 имён | 1,0 ГБ | 150–165 МБ |

### DNS

- Первый DNS-запрос новой UDP-сессии, x86, 150 с, 4 DNS-клиента под нагрузкой HTTP, `hijack-dns`
  без `sniff` перед ним (2026-10-09): sing-box 1.13.21 без патчей оставил без ответа 41 запрос из
  42 306, podkop-engine r13 — 0 из 56 346 (1.13) и 0 из 56 591 (1.14). Конфиг podkop (сначала sniff)
  этого не касается.
- DoH-сервер, который закрывает соединение HTTP/2 без GOAWAY (Quad9), паузы 0–90 с между запросами
  (2026-10-10): `unexpected EOF` в 1 запросе из 13 и у sing-box 1.13.21 без патчей, и у r13; с r14
  такой запрос повторяется по новому соединению.

### Списки

Загрузка rule-set в формате source (JSON), x86, 2026-10-18; «upstream» — код upstream, который
строил список:

| | upstream | podkop-engine |
|---|---|---|
| 100 000 подсетей: рост процесса, время | +37–42 МБ, 0,35 с | +3 МБ, 13–15 мс |
| 1 000 000 подсетей: то же | +346–392 МБ, 3,3 с | +19 МБ, 0,13 с |
| 100 000 доменов: время и память, выделенная при загрузке (бенчмарк Go) | 390 мс, 277 МБ | 24 мс, 23 МБ |

На эмуляторе aarch64 с 256 МБ JSON-список из 100 000 доменов до r15 исчерпывал память (на
135–139 МБ), с r15 загружается за 2 с.

### urltest, когда сервер отказывает

Стенд x86, четыре сервера Xray VLESS REALITY Vision с задержкой 20, 80, 110 и 150 мс, загрузка
страниц и видео 6 Мбит/с через selector над группой urltest с интервалом 30 с; sing-box 1.14.4 без
патчей против podkop-engine r21 (2026-11-03). Доля — время на первом сервере.

| Что делал первый сервер | без патчей: доля / страниц с ошибкой / видео стояло | r21 |
|---|---|---|
| умер | 17 % / 6,6 % / 29 с | 12 % / 1,1 % / 29 с |
| потери 3 % | 89 % / 0 / 33 % | 89–94 % / 0 / 30–35 % |
| потери 10 % | 78 % / 0 / 79 % | 61 % / 0,4 % / 66 % |

sing-box без патчей не подключается к Xray 26.9.9 (ниже), поэтому эти прогоны шли на серверах Xray
26.6.27; r21 дал на обоих одно и то же.

### Совместимость с серверами Xray (REALITY)

Матрица версий сервера Xray × 11 сайтов-прикрытий, отпечаток `chrome`, 2026-10-25 и 2026-11-01:

| Сервер Xray | sing-box 1.12.25–1.14.4 без патчей | podkop-engine |
|---|---|---|
| 26.7.11 и новее | отказ: он заявляет версию клиента 1.8.1, ниже `minClientVer` по умолчанию; 26.9.9 и новее ещё и отвергают ClientHello без X25519MLKEM768 | работает |
| 25.5.16 – 26.6.27 | работает | работает |
| 24.11 – 25.4.30, сайт-прикрытие выбирает X25519MLKEM768 | работает | отказ, если автосмена отпечатка (r17) не отправит первым ClientHello без X25519MLKEM768 |

Путь, где ТСПУ замораживает пачки ClientHello с X25519MLKEM768 (2026-10-25): `chrome` движка прошёл в
0 случаях из 20 и замер на 40–41 с; sing-box без патчей, в чьём ClientHello нет X25519MLKEM768, —
в 43–100 %. С автосменой отпечатка (r17) движок проходит в 18–20 случаях из 20.

## Не измерено

- Роутеры: прогоны тех же тестов на MT7621 (без AES) и Filogic 820 подготовлены, их проводит
  владелец; результаты будут добавлены сюда.
- Память под большой нагрузкой прокси, работа сутками, IPv6.
